# Описание задачи: пара инструкций итеративного ревью

Артефакт — два текста: `docs/review/critic.md` (инструкция критика) и
`docs/review/development.md` (инструкция разработки). Вместе они должны нести
процесс итеративного ревью целиком на уровне ведения — так, чтобы ручной прогон
по этим двум текстам (критик-LLM + разработка-LLM + оператор на воротах) давал
корректное ревью без какой-либо технической обвязки.

Авторство этого описания (круг 1): тезисы — пересказ разработкой каркаса
`docs/design/2026-09-01_review_redesign_skeleton.md`, принятого в обсуждении
с оператором 2026-09-01; сам каркас заземлён его решениями. Граница предмета —
решение оператора (пересказ; явного акта фиксации формулировки не было —
кандидат на фиксацию в этом круге).

## Тезисы

Покрытие:

1. Критик получает артефакт целиком и семантическое описание задачи; описание
   первого круга заземлено подтверждённым интентом оператора, и обязанность
   заземления назначена: разработка предъявляет описание оператору на входных
   воротах, до первого прохода критика.
2. Каждый круг критик проходит все тезисы описания; частичный проход и
   «проверяй только затронутое правкой» не допускаются.
3. Сверка встречная: тезис → артефакт (выполняется ли утверждение) и
   артефакт → описание (лишнее в артефакте; молчание описания о том, чего
   требует задача).
4. Критик называет ЧТО сломано через сценарий неверного результата;
   предписания КАК чинить запрещены.
5. Находки несут серьёзность и уровень достоверности (подтверждено /
   правдоподобно / спекулятивно / недостаточно данных); спекуляция не
   подаётся как факт; неоднозначность признаётся явно, а не разрешается
   молчаливым выбором одного прочтения.

Описание задачи и авторство:

6. Новый круг получает переписанное описание; дельта описания — часть
   предмета чтения критика.
7. Каждое изменение описания несёт пометку авторства; дрейф судится по
   авторству, не по размеру; дрейф без подписи — находка; семантическое
   изменение под подписью разработки — находка само по себе, и это правило
   есть у обеих ролей.
8. После пивота оператора критик прогоняет все тезисы на согласованность:
   убранное решение оставляет хвосты.

Уровни достоверности решений:

9. Три уровня: понятое решение оператора (неоспоримо по существу; проверяемо
   на верность записи, вопрос — только оператору), явно делегированное
   (оспоримо), рабочее решение разработки (оспоримо свободно).
10. Граница владения — между «что делается» и «как делается». «Что»
    (семантика) — собственность оператора, не делегируется, непонимание
    там всегда блокер; «как» — делегируемо, но только явным выбором
    оператора каждый раз, не автоматом. «Да» за пределами компетенции
    записывается делегированием; сильный уровень — только явному акту
    фиксации; дословное — только скопированное, пересказ помечается
    пересказом.
11. Когда полное понимание «как» требует знания, которого аналогия не
    доставит, разработка обязана сказать это прямо и предложить выбор:
    разбираем по-настоящему или явное делегирование; в слое «что» такого
    выбора нет — разбираем до понимания всегда. Готовое решение: намереваясь
    изобретать своё, разработка проверяет, нет ли готового (в проекте или
    общепринятого); есть — прямой вопрос оператору с обоснованием, почему
    своё лучше; критик ловит незаписанные случаи изобретения при готовом;
    решение всегда за оператором.

Разбор находок и правки:

12. Разработка разбирает каждую находку пообъектно с рассуждением; «всё
    принято» без разбора запрещено; раздел «не согласен с критиком»
    заполняется аргументами или честно опускается.
13. Неразрешённый спор критика и разработки уходит оператору. Находка,
    утверждающая расхождение артефакта с зафиксированным понятым решением
    оператора или сомневающаяся в верности его записи, не закрывается
    внутри пары ни одной из ролей — уходит оператору с позициями обеих;
    она обязана назвать конкретное решение; прочих находок правило не
    касается.
14. Любая правка = новая версия = новый полный проход критика; вердикт
    «готово после правки этих находок» запрещён; «готово, несмотря на
    мелочи» — легален.
15. Незапрошенные улучшения ограничены (не больше трёх за круг, только с
    практическим эффектом).

Подача оператору:

16. Ответ критика адресован разработке (полный разбор там — норма);
    к оператору идёт только через разработку: суть первой, две-три фразы
    на языке задачи, его развилки в полном виде, рабочий слой строкой,
    развёртка по запросу.
17. Читаемость несущая: непонимание оператора — дефект текста, не чтения.

Остановка:

18. Три пути: чистый полный проход; схождение по суждению (рекомендация
    критика одной строкой, решает оператор); слово оператора — безусловно,
    из любого состояния, с правом машинерии один раз спросить «уверен?» и
    без права отказать.
19. Каждый круг несёт строку тренда: находки новой территории / потомки
    прежних правок.
20. Жёстких потолков числа кругов нет; финализацию объявляет только оператор.

Сдерживатели:

21. Модель издержек: разработка ведётся с использованием LLM — генерация
    дешева; дороги отладка на живом, тихие отказы, дыры наблюдаемости,
    хрупкость оркестрации, когнитивная нагрузка, латентность, стоимость
    инфраструктуры и LLM-вызовов, бремя сопровождения; рост объёма
    документа — сам по себе сигнал.
22. Не выдумывать проблемы ради глубины; не придираться без практического
    эффекта; проход без находок не потрачен зря; предпочитать сжатие, не
    роняющее корректность.
23. Критик — осведомлённое мнение, не власть; между кругами прежняя критика
    не защищается ради последовательности, находка не роняется без
    материальной причины.
24. Критик уважает модель угроз артефакта: риски судятся против неё, сценарии
    вне её помечаются как выход за модель угроз; различаются блокер сейчас /
    приемлемо для MVP / риск масштаба.
25. При конфликте правил пары приоритет — дисциплине свидетельств и
    корректности над целостностью цикла, ясностью и краткостью формы.
26. Всё, чем владеет оператор — язык, модель угроз, масштаб, глубина
    объяснений, — не зашито в тексты пары, а берётся из профиля оператора;
    канон профиля — в графе памяти, в репе — его скомпилированный кэш.

Расслоение правок и гигиена разработки:

27. Правки расслоены: рабочий слой (опечатки, согласованность, перенос уже
    решённого) — рабочие решения разработки без слова оператора;
    семантические правки (меняющие гарантии, обещания, поведение) — только
    явной фиксацией оператора, допускается перечисленной пачкой одним
    ответом на нумерованный список.
28. Чёс класса: у каждой правки разработка спрашивает её класс и проходит
    его до конца, перечисляя в записи круга, где искала; правка одного
    вхождения при живом классе — незакрытая находка.
29. Само-ревью: до отправки критику разработка сама проходит артефакт по
    описанию в обе стороны и чинит найденное; само-ревью — фильтр, не
    вердикт, прохода критика не заменяет.

## Граница предмета (решение оператора, 2026-09-01)

Пара покрывает **слой ведения ревью**. Сознательно вынесены в следующий
артефакт лестницы (спеку технической обвязки): технический слой (профили
машин, наблюдатели, громкие отказы, транспорт кругов), механизм сквозного
профиля оператора (сбор сигналов парами обмена, пересборка — сам профиль
пара получает готовым: канон в графе, кэш `docs/review/operator_profile.md`),
механика выбора модели критика. Лестница целиком: тексты пары →
их ручное ревью → спека обвязки → реализация с ручным код-ревью → деплой →
живая оценка на внешнем проекте.

Молчание пары об этих слоях — не находка. Спор с самой границей легален:
«вот сценарий, где пара без этого куска даёт неверный результат» — такая
находка уходит оператору как развилка владельца.

  «в проекте или общепринятого» к пункту 7). Уровень — понятое решение
  оператора: (1) входные ворота, тезис 1; (2) незакрываемость находок по
  зафиксированным решениям, тезис 13; (3) адресат ответа критика, тезис 16;
  (4) расслоение правок, тезис 27; (5) чёс класса, тезис 28; (6) само-ревью,
  тезис 29; (7) правило готового решения, тезис 11 — заменяет прежнюю

- Тезис 7 дополнен (правило принуждения границы у обеих ролей) — реализация
  зафиксированного решения оператора о границе «что»/«как» по находке 1
  круга 2; перенос решённого, рабочий слой.
- Чёс класса правок этого круга: правило готового решения положено в обе
  инструкции и тезис 11; незакрываемость — в обе инструкции и тезис 13;
  принуждение границы — критику (у разработки граница уже была) и тезис 7.
