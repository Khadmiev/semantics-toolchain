# Круг 1 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: код до правок круга 1 (56 тестов — после).
Тренд: 13 находок новой территории / 0 потомков прежних правок.
Вердикт критика: не готова к живому прогону; решает оператор.

## Исходы (разработка)

1. Перезапуск незавершённого круга уничтожает проход — **согласен**:
   write_pass не переписывает никогда; цикл продолжает разбор с записанного
   прохода, критик не переигрывается (тест: критик запускается ровно раз).
2. Первый проход без подтверждения описания; пустое описание — **согласен**:
   входные ворота держит обвязка (без записанного подтверждения критик не
   стартует; отказ оператора — остановка с его дословным ответом); пустое
   описание отвергается на создании. Обязанность возвращена и в тезисы.
3. Состояние промежуточных ворот не восстанавливается, старый ответ
   переносится — **согласен**: файлы запросов/ответов покруговые; ответы
   ложатся долговечно раньше удаления запросов; restore видит висящие
   развилки.
4. Проба лаунчера не проверяет тело — **согласен с изменением механизма**:
   живая проверка показала, что cmd молча терпит лишнюю скобку (rc=0) —
   «разбор тела пробой» для cmd неисполним. Класс закрыт статикой
   (неэкранированная скобка в теле — отказ на генерации) и структурой
   (тело вне скобочных блоков); для sh — настоящий разбор sh -n.
5. Роль без переводов строк признаётся мёртвой — **согласен**: чтение
   почанковое, признак жизни — любые байты обеих труб (тест: стример
   точек без \n при окне меньше длительности — жив).
6. Необёрнутые исключения; несуществующие команды — **согласен**: все
   разборы JSON (мета, профиль, буфер, запросы) дают отказ с причиной и
   действием; profile-init создан; отсылки правдивы.
7. Только-чтение критика не обеспечено — **передано оператору и решено им**
   («Да, переноси»): перенесены оба готовых слоя старого контура —
   структурный страж команды (порт sandbox.py: закрыт по умолчанию, каждая
   директива песочницы обязана говорить read-only, точки проверки на записи
   профиля и на запуске, break-glass только явный и громкий) и аттестация
   по шапке вывода инструмента (не read-only или молчание — проход
   аннулируется до записи). Первоначальная позиция разработки
   (поле-аттестация + поиск флага) была слабее готового решения проекта и
   снята после проверки кода старого контура — правило готового решения
   сработало на самой разработке. Тесты: все портированные обходы.
8. Проход хранится не дословно — **согласен**: байт в байт, без strip и
   заголовков; метаданные (время получения, версия профиля) — в соседнем
   round_NN_pass_meta.json (тест точного равенства).
9. Буфер принимает половину обмена — **согласен с изменением**: реакция без
   развёртки отвергается; дисциплина «пара пишется по закрытии обмена»
   записана в код; обмен без развёртки (прямое предпочтение) легален с
   пустыми вторыми половинами — это закрытый обмен, не половинка.
10. Повторная отправка после аварии — **согласен**: буфер худеет по-штучно
    и долговечно после каждого успеха; окно дубликата — одна пара
    (точно-однократность требует идемпотентности графа — за границей среза).
11. Версия подстрокой; версия не фиксируется в круге — **согласен**:
    точное равенство по разобранной строке version:; версия кэша пишется
    в метаданные круга; тезис 19 дополнен.
12. Вне-git не обеспечено обвязкой — **согласен**: create проверяет
    git check-ignore; отслеживаемый каталог — отказ; невозможность
    проверить — тоже отказ (принцип 1).
13. Аттестация уже, чем тезисы — **согласен**: добавлены тесты на каждый
    пункт выше, включая портированные обходы стража; итог 56 passed,
    код возврата pytest 0.

## Проход критика дословно

Вердикт: текущая версия не готова к живому прогону. Найдены блокеры
восстановления, входных ворот, доставки лаунчера и сохранности семантических
решений.

1. Незавершённый круг при повторном запуске уничтожает сохранённый проход
критика. Серьёзность: критическая, блокер сейчас. Достоверность:
подтверждено. После падения разработки состояние оставляет текущий номер
прежним (runcat.py:72). Новый вызов round снова запускает критика и
безусловно переписывает тот же файл (cycle.py:69, runcat.py:126). Сценарий:
критик дал проход, разработка упала; предписанное отказом «перезапусти круг»
заменяет исходный проход новым текстом. Пережить обрыв и продолжить разбор
из файлов невозможно.

2. Первый проход может начаться без подтверждения описания оператором;
пустое описание также принимается. Серьёзность: критическая, блокер сейчас.
Достоверность: подтверждено. create сразу записывает любые переданные
строки, включая пустые, а one_round не проверяет запись входных ворот
(runcat.py:89, cycle.py:50). Сценарий: агент создаёт прогон с неполным либо
неверным описанием и запускает критика; тот честно выдаёт чистый проход
против интента, которого оператор не подтверждал. Это повторяет ровно тот
класс отказа, ради которого входные ворота внесены в спеку (спека:147).
Тезисы описания задачи эту обязанность молча опустили; граница предмета её
не исключает.

3. Состояние промежуточных ворот не восстанавливается и может перенести
старый ответ в следующий круг. Серьёзность: высокая, блокер сейчас.
Достоверность: подтверждено. Файлы запросов и ответов имеют общие для всего
прогона имена, ответы пишутся без долговечного сброса, файл запросов
удаляется до повторного запуска разработки, а файл ответов после круга
остаётся (cycle.py:28, cycle.py:83). restore ворота и висящие вопросы вообще
не читает (runcat.py:168). Сценарии: обрыв после удаления запросов оставляет
неясное висящее состояние; в следующем круге разработка видит
gate_answers.json прошлого круга и применяет старый ответ к новой развилке.
Сам тестовый агент уже ведёт себя именно так: наличие файла означает «ответ
получен» без проверки номера круга (test_cycle.py:94).

4. Проба сгенерированного лаунчера не проверяет его полезную часть.
Серьёзность: высокая, блокер доставки. Достоверность: подтверждено. Пробная
ветка завершает скрипт до исполнения тела (launcher.py:23). Поэтому реальный
интерпретатор может вернуть ноль, не дойдя до сломанного экранирования или
синтаксиса ниже. Сценарий: Windows-лаунчер содержит ту самую неэкранированную
скобку, проба объявляет его доставленным, а живой запуск падает. Отказной
тест проверяет вручную созданный файл без пробной ветки и потому этот дефект
не ловит (test_profiles_and_liveness.py:71).

5. Активная роль признаётся мёртвой, если пишет без перевода строки.
Серьёзность: высокая. Достоверность механизма: подтверждено; наступление
зависит от формата вывода конкретной команды. Обе трубы читаются построчно,
и время активности обновляется только после получения полной строки
(subproc.py:52, subproc.py:63). Сценарий: LLM-клиент стримит токены без \n,
а CLI показывает прогресс через возвраты каретки; роль работает и выдаёт
данные, но через окно обвязка убивает её как молчащую. Это практический риск
живого запуска, а не сценарий вне модели угроз.

6. Обещание «каждый отказ содержит причину и следующее действие» обходится
необёрнутыми исключениями; два названных действия не существуют.
Серьёзность: высокая. Достоверность: подтверждено. Повреждённые JSON-файлы
и отсутствующие поля дают JSONDecodeError, TypeError либо KeyError, а не
HarnessError (machine_profile.py:115, runcat.py:177, cycle.py:85). Кроме
того, отказы отправляют к profile-init и profile-refresh
(machine_profile.py:111, cycle.py:62), хотя среди четырёх команд CLI их нет
(cli.py:35). Сценарий: частично записанный профиль останавливает запуск
сырым traceback; указанное следующее действие затем завершается ошибкой
argparse.

7. Не обеспечено понятое решение оператора: критик всегда имеет только
чтение репозитория и графа. Серьёзность: высокая. Достоверность:
правдоподобно. Конкретное решение: критику изменение репозитория и запись в
граф запрещены всегда (спека:47). MachineProfile хранит команды и свободные
заметки, а общий Popen наследует окружение процесса без проверяемого
ограничения прав (machine_profile.py:30, subproc.py:31). Неоднозначность:
необходимые флаги песочницы могут быть вручную зашиты в critic_argv, но
обвязка не различает защищённую и незащищённую команду. Сценарий: профиль
указывает исполнимый клиент без режима только-чтение; критик случайно
редактирует артефакт, а проверка профиля считает запуск допустимым. Это
расхождение с конкретным решением оператора должно быть вынесено ему с
позицией разработки.

8. Проход критика хранится не дословно. Серьёзность: средняя, нарушение
несущего контракта. Достоверность: подтверждено. run_watched удаляет
начальные и конечные пробелы и переводы строк через .strip()
(subproc.py:110), затем write_pass добавляет в тот же файл собственный
заголовок и время (runcat.py:134). Сценарий: разработка или проверка подписи
читает файл как дословный результат критика, но получает изменённый текст с
добавленным содержимым обвязки. Тест проверяет лишь наличие подстроки, а не
точное равенство (test_errors_and_runcat.py:62).

9. Буфер принимает половину обмена как полную пару. Серьёзность: высокая
для качества профиля. Достоверность: подтверждённое поведение, семантическое
прочтение явно неоднозначно. Валидация требует только первую формулировку и
сигнал оператора; развёртка и реакция могут отсутствовать
(profile_sync.py:48). Тесты регулярно сохраняют пары с двумя пустыми
половинами (test_profiles_and_liveness.py:112). Сценарий: сигнал «разверни»
фиксируется до развёртки и реакции; при пересборке невозможно сравнить
содержание двух формулировок, хотя именно это сравнение определяет смысл
сигнала. Комментарий к полям разрешает пустоту, тогда как спека требует
пары обмена целиком — это влияющее на данные разночтение.

10. Успешно отправленная пара остаётся в буфере до завершения всей досылки
и после аварийного обрыва отправляется повторно. Серьёзность: высокая,
порча данных. Достоверность: подтверждено. После каждого успешного send_pair
файл не меняется; хвост переписывается только при обработанном исключении
или после полного успеха (profile_sync.py:99). Сценарий: первая пара попала
в граф, процесс завершился до второй; новая сессия восстановит исходный файл
и отправит первую пару ещё раз. При медленно растущем графе дубликаты
искажают сырьё профиля. Существующий тест покрывает лишь исключение, которое
код успел поймать, но не аварийный обрыв между успешными отправками.

11. Контент-адресуемая версия профиля сравнивается неточно и не фиксируется
в круге. Серьёзность: средняя сейчас, высокая при накоплении прогонов.
Достоверность: подтверждено. Версия ищется как подстрока в первых трёх
строках: новая версия aaa считается уже записанной при старой baaa
(profile_sync.py:139). Сам цикл извлекает только notify-within, а метаданные
прогона версии профиля не содержат (cycle.py:57, runcat.py:116). Сценарий:
профиль сменился между кругами, обновление ошибочно подавлено либо кэш
изменился позже; из каталога нельзя установить, по какой версии подачи
работали роли. Обязанность фиксировать версию есть в спеке, но отсутствует
в тезисах без пометки оператора (спека:120).

12. Решение оператора «каталог прогона вне Git» зависит от дисциплины
вызывающего, а не обеспечивается обвязкой. Серьёзность: высокая при
срабатывании; для текущего пути риск снижен существующим .gitignore.
Достоверность: правдоподобно. Конкретное решение оператора зафиксировано в
спеке (спека:69). CLI принимает произвольный run_dir, а RunCatalog.create
не проверяет расположение или игнорирование Git (cli.py:35, runcat.py:89).
Текущий docs/review/*/ действительно игнорируется, поэтому именно этот
запуск защищён. Сценарий ошибки: следующий оператор создаёт каталог по
допустимому для CLI пути внутри отслеживаемой части репозитория; приватная
цитата попадает в публикацию. Это риск прямо внутри объявленной модели угроз
и расхождение с конкретным решением оператора.

13. Зелёная аттестация не покрывает заявленные отказные ветки и пропускает
перечисленные дефекты. Серьёзность: высокая, блокер приёмки. Достоверность:
подтверждено. Штатный запуск дал 31 passed, однако нет сценариев повторного
запуска незавершённого круга, пустого/неподтверждённого описания,
сгенерированного лаунчера со сломанным телом, вывода без перевода строки,
аварии между успешными отправками, перехода версии-подстроки и переноса
ответов между кругами. Поэтому код возврата pytest сейчас подтверждает
только более узкий контракт, чем заявленный тезисами.

Остальной полный проход: явная модель критика, защита непустого каталога,
базовая проверка окон и исполняемых файлов, чтение notify-within, четыре
команды CLI, отсутствие потолков/вердиктов и регистрация пакета реализованы
без найденного практического расхождения.

Строка тренда: 13 находок на новой территории / 0 потомков прежних правок.
Репозиторий и граф не изменялись.
