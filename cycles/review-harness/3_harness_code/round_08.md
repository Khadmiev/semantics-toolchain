# Круг 8 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после правок круга 7 (94 теста).
Тренд: 2 находки новой территории / 4 потомка прежних правок.
Вердикт критика: не готова — privacy-семантика требует решения оператора,
privacy-отказ не убивает роль; решает оператор.

## Исходы (разработка; 95 тестов, pytest exit 0)

1. Ослабление решения оператора о приватности — **находка уровня решения
   владельца; закрыта ВОЗВРАТОМ к его решению, доложено оператору**.
   Критик прав: замена «вне git по построению» на «допуск записи до тика»
   была рабочим решением разработки, менявшим то, чем система рискует, —
   без права на это. Спора с решением у разработки нет; вместо ослабления
   гарантия возвращена по построению: стримы ролей (partial, журнал
   разработки) живут в системном temp ВНЕ любого репозитория и попадают в
   каталог прогона только долговечной записью с проверкой приватности.
   Байты середины роли рабочей копии не касаются вовсе. Позиции сторон и
   возврат доложены оператору. ОТВЕТ ОПЕРАТОРА (дословно): «предыдущая —
   да, была моей и я с ней согласен по-прежнему» — гарантия «вне git по
   построению» подтверждена как его понятое решение; формулировку
   разработки про механизм он не понял (сигнал провала перевода записан),
   развёртка дана и принята без возражений. Механизм (стримы в системном
   temp) — «как», рабочий слой разработки.
2. Privacy-отказ не убивает дерево — **согласен**: всё тело run_watched —
   замыкание под единственным try: ЛЮБОЙ отказ (privacy, диск, прочее)
   сначала убивает дерево, потом уходит наверх. Доказательство в тесте —
   пульс DEVNULL-помощника останавливается после privacy-отказа.
3. Запись ворот — не восстановимое состояние — **согласен**: состояние
   первично, журнал производен. Дословный ответ входных ворот ложится
   ОДНОЙ долговечной записью вместе с флагом (run.json); ответ пачки — в
   долговечный JSON до журнала. Обрыв между записями не рождает повторного
   вопроса; отказ входных ворот журналируется (переспрос легален — ворота
   не пройдены).
4. Контракт файловых отказов частичен — **согласен**: контрактные
   read_text/read_bytes применены ко всем чтениям (журнал ворот, кэш
   профиля оператора, артефакты снимка, сопроводиловка, буфер, CLI),
   записи кэша/профиля обёрнуты; битые кодировки — тот же контракт.
5. Противоречие {launch_note} в описании — **согласен**: первая половина
   тезиса 7 переписана ({model} у критика; сопроводиловка — stdin «-»
   штатно, {launch_note} только break-glass).
6. Исходы мимо долговечного API — **согласен**: цикл пере-долговечивает
   исходы своим API (fsync + приватность) до признания круга завершённым.

## Проход критика дословно

Тесты проходят: 94 passed. Закрыты POSIX PGID, префикс outcomes и
структурные проверки под python -O. Однако privacy-правка внесла
несанкционированное семантическое ослабление и не выполняет даже новое
обещание остановки роли.

1. [CRITICAL, подтверждено] Решение оператора о privacy ослаблено рабочим
решением разработки. Зафиксированное решение: каталог прогона и буфер вне
Git по построению. В круге 8 разработка самостоятельно заменила эту
гарантию на допуск записи в отслеживаемый каталог в течение тика, назвав
это «предотвращением». Это изменение того, чем система рискует, а не
только механики. Оно подписано рабочим решением разработки, поэтому пара
не вправе закрыть его самостоятельно. Сценарий: после удаления .gitignore
приватные байты до секунды записываются в Git-visible файлы. Раньше
описание обещало невозможность такого состояния; теперь оно объявлено
допустимым без подтверждения владельца. Позиция разработки: абсолютный
перехват stream-записей недостижим, секундный надзор достаточен. Позиция
критика: это материально более слабая гарантия. Вопрос только оператору:
уверены, что решение было понято и принято именно как допуск Git-visible
записи приватных данных на время до одного тика? Класс: блокер решения
владельца; потомок privacy-находки.

2. [CRITICAL, подтверждено] Privacy-отказ вообще не убивает дерево роли.
В monitor-loop privacy_check() вызывается напрямую; HarnessError выходит
из run_watched() без tree.kill() и без общего cleanup-finally. Сценарий:
разработка удаляет .gitignore, запускает DEVNULL-помощника и продолжает
работу; privacy-check бросает отказ, harness возвращает управление, но
родитель и помощник остаются живы. Новый тест проверяет только скорость
возврата, не heartbeat процесса после отказа. Класс: MVP-блокер изоляции.

3. [HIGH, подтверждено] Долговечная запись ворот не является восстановимым
состоянием. Gate.ask() сначала пишет вопрос и ответ в gates.md, затем
вызывающий отдельно записывает состояние (флаг в run.json; JSON ответов).
Сценарий входа: оператор подтвердил, ответ в gates.md, обрыв до
mark_entry_confirmed() — после рестарта подтверждение спрашивается
повторно. Сценарий пачки: ответ в gates.md, обрыв до JSON — тот же вопрос
задаётся снова, два дословных ответа могут различаться. Класс: MVP.

4. [HIGH, подтверждено] Контракт файловых отказов покрывает только часть
путей: чтение gates.md, operator profile, артефактов при snapshot, launch
note, pair buffer/cache, description и launch note в CLI — необёрнуты.
Битая UTF-8 или ошибка доступа — сырой UnicodeDecodeError/OSError. Класс:
MVP; потомок disk-error-находки.

5. [MEDIUM, подтверждено] Противоречие {launch_note} осталось в описании:
тезис требует и {model}, и {launch_note}, ниже объявляет штатным только
stdin «-». Следующий разработчик, исполнив первое, аннулирует запуск.
Класс: сопровождение.

6. [MEDIUM] Активный цикл принимает outcomes, записанные мимо долговечного
API: headless-разработка пишет write_text, цикл проверяет существование и
непустоту; сбой питания до сброса кэша теряет исходы, считавшиеся
долговечными. Класс: риск порчи данных.
