# Круг 9 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после правок круга 8 (95 тестов).
Тренд: 4 находки новой территории / 5 потомков прежних правок.
Вердикт критика: не готова; решает оператор.

## Исходы (разработка; 98 тестов, pytest exit 0)

1. Privacy «по построению» не восстановлено полностью — **РАЗВИЛКА
   ОПЕРАТОРА, РЕШЕНА ИМ** (дословно: «в игнор она — чтобы репу не
   засирать»): правило игнора — гигиена дерева, не оборона; злонамеренный
   коммитер на личной машине вне модели угроз, публикация закрыта уровнем
   R1.1 (рабочая репа не публикуется вовсе). Каталоги остаются в репе под
   игнором, существующие страховки сохранены, новых укреплений класс не
   требует; секундное окно после смены .gitignore дефектом не является.
   Критик защищал шире объявленной модели угроз. Изначальная передача: Критик прав
   фактически: в temp вынесены только захваченные потоки, а сам каталог
   прогона живёт в репозитории под .gitignore — удаление правила мгновенно
   делает прошлые проходы Git-visible, и headless-роль пишет исходы прямо
   в каталог до следующего тика. Позиция критика: «по построению» требует
   вынести каталог целиком. Позиция разработки: у решения оператора две
   честные формы — «в репе под игнором» (его дословное «каталоги прогонов
   в гитигнор») и «вне репы вовсе» (буквальное «по построению» из спеки);
   выбор между ними принадлежит оператору. Рекомендация разработки:
   вынести каталоги прогонов И буфер целиком вне репозитория
   (пользовательский каталог данных), в репе оставить только неприватное
   (профиль машины); класс закрывается терминально, цена — прогоны не
   видны в дереве репы (путь печатается обвязкой).
2. Отказ открытия стрима оставляет роль живой — **согласен**: tree.kill()
   до отказа; страховочный обработчик не молчит о неподтверждённой смерти
   (дописывает это в отказ с действием «добей вручную»).
3. Контракт кодировок частичен — **согласен**: единый контрактный читатель
   (диск + кодировка) во всех чтениях каталога, меты, профиля, исходов.
4. История нераспознанных ответов теряется — **согласен**: промежуточные
   ответы журналируются немедленно; финальный по-прежнему идёт одной
   долговечной записью в состояние.
5. Частичная пачка считается закрытой; повторная подача после довершения —
   **согласен**: pending сравнивает длины запросов и ответов; после
   второго прогона разработки повторный файл запросов — отказ.
6. «Байт в байт» и не-UTF-8 — **согласен**: backslashreplace вместо «�» —
   свидетельство сохраняется видимыми эскейпами.
7. Профиль без окружения — **согласен**: поле env в профиле машины,
   накладывается поверх окружения обвязки при старте обеих ролей
   (спека: «команда, окружение, песочница»); тезис 7 дополнен.
8. Развёртка без реакции принимается — **согласен**: отвергается в обе
   стороны; «(реакции не последовало)» записывается явным текстом.
9. fsync каталога после replace — **согласен**: на POSIX добавлен fsync
   записи каталога; на Windows replace журналируется NTFS.

## Проход критика дословно

Полный проход круга 9 выполнен. Тесты проходят: 95 passed, но они не
покрывают несколько сохраняющихся отказов.

1. [CRITICAL, подтверждено] Понятое решение оператора «каталог прогона и
приватные данные вне Git по построению» фактически не восстановлено. В
temp вынесены только stdout/stderr; каталог остаётся внутри репозитория,
а headless-разработка пишет outcomes и запросы ворот прямо туда. Сценарий:
разработка удаляет .gitignore; все прежние проходы сразу становятся
Git-visible, затем outcomes с приватной цитатой записываются до следующего
тика. Надзор обнаруживает уже возникшее состояние, но не предотвращает
его. Позиция разработки: перенос stream-файлов вернул гарантию. Позиция
критика: перенос покрывает только захваченные потоки, но не сам каталог и
файлы, которые роль создаёт напрямую. Класс: блокер понятого решения
оператора; в модели угроз; потомок privacy-находки.

2. [HIGH, подтверждено] Отказ открытия stream-файла по-прежнему оставляет
уже запущенную роль живой: между Popen и обработчиком нет tree.kill();
тест проверяет только исключение, не смерть процесса; общий обработчик
игнорирует отрицательный результат убийства дерева. Класс: MVP-блокер
живучести.

3. [HIGH, подтверждено] Контракт «любая дисковая ошибка или битая кодировка
— HarnessError» частичен: _read_text ловит только OSError; мета круга,
gate-файлы, machine profile и outcomes не ловят UnicodeDecodeError;
mkdir/unlink и часть записей необёрнуты. Класс: MVP.

4. [HIGH, подтверждено] Исправление входных ворот потеряло историю
нераспознанных ответов: переспросы идут с record=False, возвращается
только последний ответ. «Не уверен» → «да» превращается в каталоге в одно
безусловное «да» вопреки тезису 14. Класс: MVP, искажение слова оператора.

5. [HIGH, подтверждено] Состояние промежуточных ворот восстанавливается
неверно: pending считается по наличию файлов ответов — частично отвеченная
пачка выглядит закрытой; повторный gate-файл второй сессии разработки после
ответов не проверяется перед завершением круга. Класс: MVP; новая
территория.

6. [MEDIUM, подтверждено] «Байт в байт» не выполняется: декодер заменяет
ошибочные байты на «�» — точное свидетельство ошибки Windows-инструмента
теряется. Класс: доказательность; новая территория.

7. [MEDIUM, подтверждено] Профиль машины не сохраняет окружение запуска,
хотя спека определяет профиль как «команда, окружение, песочница»; Popen
наследует случайное окружение оболочки; описание требование опустило.
Сценарий: профиль работал с конкретным CODEX_HOME/proxy, следующая сессия
стартует из другой оболочки — другая авторизация или падение. Класс:
MVP-риск запуска; новая территория.

8. [MEDIUM, подтверждено] «Пара обмена целиком» не обеспечена: валидатор
принимает развёртку без реакции — компилятор профиля не может определить,
помог ли перевод, но полпары выдаётся за сырьё. Класс: тихое искажение;
новая территория.

9. [MEDIUM, правдоподобно] Атомарная запись не сбрасывает запись каталога
файловой системы после os.replace — на POSIX внезапное отключение питания
может вернуть старый run.json; отвеченный вопрос повторяется или
подтверждение теряется. Класс: платформенный риск порчи данных.

Вердикт: не готова; финализацию решает только оператор.
