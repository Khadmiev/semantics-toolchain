# Круг 4 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после классовых правок круга 3
(78 тестов). Тренд: 2 находки новой территории / 7 потомков прежних правок.
Вердикт критика: существенно укреплена, к живому прогону не готова;
решает оператор.
Материально закрыты: белый список на уровне шаблона, "false"-break-glass,
разбор реального формата, пустые исходы, частичная пачка, восстановленная
пара.

## Исходы (разработка; все — рабочий слой; 85 тестов, pytest exit 0)

1. Белый список отвергает собственную команду после подстановки —
   **согласен, конфуз**: страж судит ШАБЛОН профиля (подстановка
   детерминирована), а подставляемые значения валидируются как значения
   (модель — идентификатор, сопроводиловка — существующий файл; инъекция
   флагов через значение закрыта). Seam-тест штатного маршрута добавлен.
2. Приватность после стрима — **согласен**: проверка стоит в начале круга,
   до запуска критика и первого частичного файла; тест: git init без
   игнора → отказ до старта критика, partial отсутствует.
3. Наличие меты принято за полноту — **согласен**: artifact_snapshot и
   operator_profile_version обязательны и типизированы; проверка на
   записи, чтении и restore (мета всех проходов читается при
   восстановлении).
4. Исходы без прохода восстанавливаются как здоровые — **согласен**:
   инвариант проверяется, осиротевшие исходы — отказ восстановления.
5. DEVNULL-сирота невидим — **согласен, класс закрыт структурно**: роль
   живёт в Windows Job Object (kill-on-close, через ctypes) или своей
   группе процессов (POSIX); завершение роли любым исходом закрывает всё
   дерево независимо от труб. Сирота с унаследованными трубами теперь
   тоже добивается, и роль завершается честным успехом без зависания.
6. «немедленно/непременно» читаются отказом — **согласен**: морфологическое
   отрицание сужено до утвердительных основ («несогласен» — отказ,
   «да, немедленно финализируй» — согласие).
7. Порча элементов ворот — сырой KeyError — **согласен**: структура
   элементов запросов и ответов проверяется, порча — отказ с причиной.
8. Снимок ≠ предмет суда — **согласен** (уточнение моего рабочего решения
   по разбору критика): в снимок входят артефакты И описание задачи
   (его уточнение — новая версия, новый проход), git-голова исключена из
   сравнения (посторонний коммит — не правка) и пишется как происхождение.
9. Аттестация не исполняет штатный маршрут — **согласен**: seam-тест
   безопасного пути с включённым стражем и настоящей подстановкой
   (монкипатч только на границе субпроцесса), тесты приватного partial,
   неполной меты, сироты, «немедленно», порчи ворот, смены описания.
   Итог: 85 passed, код возврата pytest 0, линт чист.

## Проход критика дословно

Вердикт: версия существенно укреплена, но к живому прогону ещё не готова.
Главный штатный путь read-only сейчас вообще не запускается, а несколько
классовых исправлений всё ещё защищают только часть путей записи и
восстановления.

1. Белый список принимает шаблон команды, но отвергает ту же команду после
обязательной подстановки. Серьёзность: критическая, блокер MVP.
Достоверность: подтверждено. Потомок находок 1–2 прошлого круга. В профиле
разрешено только буквальное значение {model} после -m и буквальный
позиционный {launch_note} (readonly_guard.py). Перед запуском оба маркера
заменяются реальной моделью и путём, после чего страж вызывается повторно
(critic.py). Поэтому прошедшая profile-check команда codex exec -s
read-only -m {model} {launch_note} превращается в … -m gpt-5.6-sol
D:\…\launch_critic.md и немедленно отвергается собственным стражем. Без
break-glass безопасный живой критик не может стартовать ни разу.

2. Приватность проверяется перед финальными файлами, но не перед фактическим
стримом приватного текста. Серьёзность: критическая для модели угроз
публикации. Достоверность: подтверждено. Потомок находки 6. Новый проход
сначала стримится напрямую в round_NN_pass.partial (cycle.py); проверка Git
происходит позже, внутри write_pass (runcat.py). Если каталог перестал
игнорироваться между кругами, полный вывод критика уже оказывается в
публикуемом рабочем дереве до отказа. Тем же прямым путём пишется журнал
разработки (cycle.py), а очистка или перезапись буфера после flush не
повторяет проверку приватности (profile_sync.py). Тест проверяет только
прямой вызов write_pass, поэтому этот сценарий не видит.

3. Наличие файла метаданных принято за полноту метаданных. Серьёзность:
высокая, блокер восстановления. Достоверность: подтверждено. Потомок
находки 5. read_round_meta требует только JSON-объект, но не обязательные
artifact_snapshot и operator_profile_version и не их типы (runcat.py). При
продолжении оба поля условны: если их нет, проверки просто пропускаются
(cycle.py). Метаданные {"received_at":"…"} позволяют продолжить разбор
вслепую — тот самый сценарий, который дельта объявляет закрытым.
Дополнительно мета завершённых кругов вообще не читается при restore: её
удаление не мешает status или переходу к следующему кругу, хотя
восстановить «какая версия судилась» уже невозможно.

4. Повреждённое состояние кругов восстанавливается как здоровое, если имена
файлов синтаксически правильны. Серьёзность: высокая. Достоверность:
подтверждено. Новая территория. restore независимо собирает номера проходов
и исходов, не проверяя их взаимные инварианты (runcat.py). Сценарий: в
каталоге лежит непустой round_02_outcomes.md, но нет прохода второго круга.
Восстановление не отказывает; позднее второй круг может принять этот старый
файл как результат только что запущенной разработки, даже если она новых
исходов не записала. Каталог сообщает завершённый разбор, которого не было.

5. Дочерний процесс без унаследованных труб остаётся полностью невидимым.
Серьёзность: критическая для живучести и сохранности данных. Достоверность:
подтверждено. Потомок находки 7. После выхода родителя дерево проверяется
только косвенно — по живым потокам чтения stdout/stderr (subproc.py). Если
родитель запускает помощника с перенаправленными в DEVNULL трубами и
завершается с кодом 0, оба потока закрываются, _kill_tree не вызывается и
роль считается успешно законченной. Помощник продолжает менять репозиторий
после объявленного завершения. Новый тест покрывает только сироту, который
наследует и держит трубы.

6. Морфологическое отрицание стало поглощать обычные утвердительные слова.
Серьёзность: высокая для безусловного слова оператора. Достоверность:
подтверждено. Потомок находки 8. Любое слово, начинающееся с не, делает
весь ответ отрицательным до разбора явного да (gates.py). Поэтому ответы
«Да, немедленно финализируй» и «непременно согласен» возвращают False:
немедленно и непременно грамматически не являются отрицаниями, но совпадают
с префиксной эвристикой. Явное согласие оператора снова исполняется
наоборот.

7. Семантически повреждённые файлы ворот дают сырой traceback. Серьёзность:
средняя для MVP, высокая при восстановлении после ручной порчи.
Достоверность: подтверждено. Новая территория. Проверяется лишь то, что
верхний JSON — список; элементы и обязательные поля не проверяются.
round_01_gate_answers.json со значением [{"answer":"да"}] падает с
необработанным KeyError при построении множества вопросов (cycle.py).
Аналогично элемент запроса без question падает внутри цикла. Обещание
«любой отказ содержит причину и следующее действие» и громкая обработка
повреждённого каталога здесь не выполняются.

8. Снимок версии артефакта не совпадает с тем, что определяет необходимость
нового полного прохода. Серьёзность: высокая для корректности автоведения.
Достоверность: подтверждено с неоднозначностью рабочего решения. Потомок
находки 11. run_cycle сравнивает только _artifact_snapshot, куда входят
перечисленные пути и вся Git-голова (cycle.py). Изменение
task_description.md внутри игнорируемого каталога прогона не замечается:
после уточнения семантики без изменения кода цикл останавливается, и критик
не видит новое описание. Обратный сценарий: посторонний коммит либо
появление служебного файла внутри каталога артефакта меняет снимок и
запускает лишний дорогой проход, хотя судимый текст не изменился. Здесь
рабочий критерий остановки разработки стал фактическим семантическим
поведением обвязки.

9. Зелёная аттестация снова не исполняет штатный безопасный маршрут.
Серьёзность: высокая, блокер приёмки. Достоверность: подтверждено. Потомок
находки 13. Заявленный запуск дал 78 passed за 90,59 с, код возврата 0. Но
тест стража проверяет только шаблон с {model} и {launch_note}, а все тесты
полного цикла используют Python-команды с allow_unsafe_critic_sandbox=True.
Поэтому обязательная повторная проверка уже подставленного argv не
выполняется ни одним интеграционным тестом. Также отсутствуют сценарии:
приватный .partial после смены Git-видимости, сирота с закрытыми трубами,
неполная мета, исходы без прохода, слова «немедленно/непременно» и
структурно повреждённые элементы файлов ворот.

Материально закрыты: чёрный список действительно заменён белым на уровне
шаблона; строковое "false" больше не открывает break-glass; реальный формат
вывода Codex разбирается корректнее; пустые исходы отвергаются; частично
отвеченная пачка и восстановленная пара получили симметричную обработку.

Строка тренда: 2 находки на новой территории / 7 потомков прежних правок.
Репозиторий и граф не изменялись. Установленный скилл итеративного ревью
не использовался.
