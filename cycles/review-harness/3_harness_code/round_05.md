# Круг 5 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после правок круга 4 (85 тестов).
Тренд: 2 находки новой территории / 7 потомков прежних правок.
Вердикт критика: не готова — безопасный путь реального запуска критика
фактически неработоспособен; решает оператор.

## Исходы (разработка; все — рабочий слой; 87 тестов, pytest exit 0)

1. Аттестация проверяет не тот поток — **согласен, и это перенос готового
   знания**: шапка codex печатается в STDERR (isolation.py аудиторного
   жанра прямо это фиксирует и склеивает stderr-первым). run_watched
   возвращает оба потока; транскрипт критика = stderr + stdout; аттестация
   и разбор содержимого — по транскрипту. Seam-тест воспроизводит реальное
   разделение потоков.
2. Launch note не доставляется детерминированно — **согласен**: для codex
   exec позиционный аргумент — ТЕКСТ инструкции, а не путь; сопроводиловка
   теперь подаётся содержимым через stdin (позиционный «-», run_watched
   получил input_text); белый список требует «-», путь-позиционал
   отвергается; {launch_note} в argv остаётся только под break-glass.
3. Очистка дерева не на всех путях — **согласен**: pgid снимается при
   старте (после reap родителя его не спросить); недоступный Job Object —
   fail-closed отказ запуска, а не тихое ослабление; DEVNULL-сирота покрыт
   живым тестом пульса (ребёнок без труб умирает вместе с ролью).
4. «Полные metadata» не описывают версию — **согласен**: полнота = версия
   подачи + git-голова + снимок, покрывающий ровно артефакты прогона плюс
   описание и сопроводиловку; фиктивный словарь полнотой не является;
   тестовые константы приведены к честному виду.
5. Пустые outcomes после повреждения — **согласен**: восстановление
   проверяет непустоту исходов каждого завершённого круга.
6. «Да, не возражаю» / «Не против» — отказ — **согласен**: идиомы согласия
   с частицей «не» схлопываются в утверждение до скана отрицаний.
7. Автоцикл не судит launch note; судит __pycache__ — **согласен**: снимок
   = артефакты + описание + сопроводиловка (весь вход критика);
   генерируемый мусор исключён из хеширования.
8. Ошибка открытия stream-файла — процесс без надзора — **согласен**:
   открытие обёрнуто; неудача убивает запущенное дерево и даёт отказ с
   причиной и действием.
9. Аттестация не исполняет безопасный маршрут — **согласен частично,
   с честной границей**: seam-тест теперь моделирует реальное разделение
   потоков и stdin-доставку, добавлены тесты DEVNULL-сироты, открытия
   стрима, идиом, глубокой полноты меты, пустых исходов. Живой запуск
   настоящего codex юнит-слоем не воспроизводится — это первая проба
   деплоя, и граница названа в дельте описания.

## Проход критика дословно

Тесты проходят: 85 passed. Однако текущая версия не готова: безопасный путь
реального запуска критика остаётся фактически неработоспособным.

1. [CRITICAL, подтверждено] Аттестация проверяет не тот поток.
run_watched() возвращает только stdout, а stderr собирает отдельно и
отбрасывает при успешном завершении (subproc.py). Затем run_critic() ищет
заголовок Codex именно в возвращённом тексте (critic.py). При этом уже
существующий код проекта прямо фиксирует, что заголовок с sandbox/model
печатается в stderr, и поэтому объединяет stderr + stdout (isolation.py).
Сценарий: реальный Codex корректно запускается в read-only, пишет
нормальное ревью в stdout, но аттестация не видит заголовок и аннулирует
каждый такой проход как небезопасный. Класс: MVP-блокер, потомок
исправлений безопасного запуска из предыдущей итерации.

2. [HIGH, подтверждена механика / правдоподобен результат] Содержимое
launch note не передаётся детерминированно. После подстановки {launch_note}
аргументом CLI становится путь к файлу (critic.py). Для codex exec
позиционный аргумент является текстом начальной инструкции; сам по себе
путь не является командой прочитать файл. Safe-profile одновременно:
запрещает полноценный шаблон вроде «Прочти {launch_note}»; допускает «-»,
но run_watched() не подаёт launch note через stdin; требует наличие
{launch_note} в разрешённой позиции. Сценарий: критик получает только
строку пути, просит уточнить задачу либо выдаёт произвольный непустой
ответ. Harness принимает этот ответ как завершённое ревью. Класс:
MVP-блокер после устранения пункта 1; новая область.

3. [HIGH, подтверждено] Обещанная очистка дерева процессов не обеспечена
на всех заявленных путях. На POSIX идентификатор process group
запрашивается уже после того, как poll() мог окончательно reap-нуть
родителя (subproc.py); ProcessLookupError тогда просто прекращает очистку
группы. На Windows Job Object присоединяется после Popen, оставляя окно
для раннего потомка; если создание или присоединение Job Object не
удалось, Windows-fallback для очистки отсутствует. Сценарий: критик
завершает родительский процесс с кодом 0, оставив потомка с DEVNULL.
Pipes закрыты, harness объявляет успех, а процесс продолжает работу после
завершения роли. Тест с названием про DEVNULL фактически запускает
потомка с унаследованными потоками — он проверяет более лёгкий случай.
Класс: MVP для инварианта изоляции ролей; потомок прошлого finding.

4. [HIGH, подтверждено] «Полные metadata» всё ещё могут не описывать
оцениваемую версию. Проверка требует лишь непустой словарь
artifact_snapshot и версию профиля (runcat.py). Она не требует git_head,
__task_description__ и соответствия ключей snapshot реальным artifact_paths
запуска. Это отражено и в тестовой константе: metadata с единственным
фиктивным x.py считаются полными для любого набора артефактов. Сценарий:
частично повреждённый каталог восстанавливается как здоровый и продолжает
цикл, хотя определить версию фактически рассмотренных файлов уже
невозможно. Класс: MVP для восстановления; потомок прошлого finding.

5. [HIGH, подтверждено] Пустые outcomes после повреждения превращаются в
успешный завершённый проход. Активный путь запрещает записывать пустой
список outcomes; восстановление проверяет наличие файла и связь с pass,
но не непустое содержимое. Сценарий: завершённый outcomes обрезан до
корректного пустого; после рестарта каталог признаёт проход завершённым и
двигает current pointer. Класс: MVP; потомок findings о восстановлении.

6. [MEDIUM, подтверждено] Обычные утвердительные фразы классифицируются
как отказ: «Да, не возражаю», «Не против» дают False из-за отрицательного
токена «не». Сценарий: оператор одобряет решение естественной русской
фразой, цикл записывает противоположный исход. Класс: MVP-ошибка
управления решением; потомок прошлого finding о морфологии.

7. [MEDIUM, подтверждено] Автоцикл не считает launch note частью входа
критика; _judged_snapshot() не учитывает launch_critic.md (cycle.py) —
исправленная инструкция критика не запускает ни одного прохода.
Одновременно рекурсивное хеширование каталогов учитывает генерируемые
файлы вроде __pycache__ — ложное обнаружение изменения предмета. Класс:
MVP для корректности автоостановки; потомок finding о snapshot identity.

8. [HIGH, подтверждено] Ошибка открытия stream-файла оставляет уже
запущенный процесс без надзора: процесс создаётся раньше, чем открывается
файл потоковой записи; исключение открытия уходит наружу сырым, а процесс
критика продолжает работать без контроля. Класс: MVP для fail-closed;
новая область.

Тренд: 2 новой территории / 7 потомков. Шаблонный guard, предварительная
privacy-проверка и структурная проверка gate заметно усилены; главный
безопасный маршрут закрыт лишь на уровне unit seam (синтетический
объединённый transcript не воспроизводит реальное разделение
stderr/stdout). Вердикт: не готова к принятию; решение о финализации
остаётся за оператором.
