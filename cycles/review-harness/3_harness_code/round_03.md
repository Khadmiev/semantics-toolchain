# Круг 3 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после правок круга 2 (70 тестов).
Тренд: 2 находки новой территории / 11 потомков прежних правок.
Диагноз критика методу: «исправления закрыли контрольные примеры, но не
классы отказов» — принят разработкой; правки этого круга классовые.
Вердикт критика: к живому прогону не готова; решает оператор.

## Исходы (разработка; 78 тестов после правок, pytest exit 0)

1. Страж пропускает -o (codex сам пишет файл) — **согласен, класс закрыт
   инверсией**: страж переведён с чёрного списка на белый — разрешено
   только нужное нашему запуску (codex exec, один pin read-only, один
   -m {model}, опционально -C, один источник промпта); любой неизвестный
   флаг, включая будущие версии codex, — отказ по построению.
2. {model} в любом месте argv не гарантирует передачу модели — **согласен**:
   белый список требует {model} строго значением -m/--model; литеральная
   модель и маркер в тексте промпта — отказ.
3. Строка "false" открывает break-glass — **согласен**: все поля профиля
   проверяются по типам во время исполнения с отказом «причина+действие».
4. Реальная шапка codex маскирует пустой ответ — **согласен**: разбор
   реального формата (сверен с probe.log): шапка между разделителями,
   эхо после «user», ответ после маркера «codex»; содержательная часть —
   только после маркера; тесты на реальном формате.
5. Проход и мета — не одно состояние — **согласен**: мета (снимок
   артефакта + версия профиля) ложится РАНЬШЕ прохода внутри write_pass;
   обрыв даёт «мета без прохода» (безвредно), никогда наоборот;
   продолжение без меты — громкий отказ вместо молчаливого {}.
6. Git-защита только при создании — **согласен**: приватность проверяется
   на каждой долговечной записи каталога И буфера.
7. Сирота переживает успешный выход родителя — **согласен с уточнением
   поведения**: после выхода родителя остаток дерева добивается; если
   сирота держит трубы и смерть дерева не подтверждена (Windows не
   раскручивает дерево мёртвого родителя) — громкий отказ с сохранённым
   выводом, НЕ молчаливый успех; код taskkill проверяется.
8. «несогласен» исполняется как согласие — **согласен**: слово,
   начинающееся с «не», утверждением не считается; тесты морфологии.
9. Ответы пачки долговечны только в конце — **согласен**: файл ответов
   переписывается после каждого ответа; частично отвеченная пачка
   продолжается с неотвеченного (по совпадению вопроса).
10. Восстановленная пара не валидируется — **согласен**: pending()
    прогоняет ту же валидацию, что append; повреждённая строка — отказ
    с номером строки.
11. Реализован круг, не цикл — **согласен**: run_cycle + команда cycle;
    критерий продолжения (рабочее решение разработки): артефакт изменился
    против снимка, который видел критик, → следующий полный проход без
    оператора; не изменился → стоп и слово оператора, вердикта у обвязки
    нет.
12. Пустые исходы = разбор — **согласен**: пустой или отсутствующий файл
    исходов — отказ; write_outcomes пустое отвергает.
13. Аттестация уже контракта — **согласен**: тесты на каждый класс выше,
    включая реальный формат вывода, сироту после успеха, частичную пачку,
    "false", смену git-видимости между кругами, автоведение. 78 passed.

## Проход критика дословно

Вердикт: текущая версия к живому прогону не готова. 70 тестов проходят, но
сохраняются обходы базовых гарантий: критик может писать в репозиторий,
модель может быть подменена умолчанием, а после аварии теряется
идентичность судившейся версии. Решение о финализации остаётся за
оператором.

1. Страж read-only пропускает штатный флаг Codex, который сам пишет файл.
Серьёзность: критическая, блокер MVP. Достоверность: подтверждено. Потомок
находки 2 прошлого круга. Список запретов в readonly_guard.py не учитывает
-o/--output-last-message. Команда codex exec -s read-only -m {model} -o
pyproject.toml {launch_note} проходит обе проверки, после чего сам CLI
записывает последний ответ в репозиторий. Шапка при этом честно говорит
sandbox: read-only, поэтому послезапусковая аттестация тоже принимает
проход. Нарушается абсолютный запрет записи критиком из тезиса 22.

2. Наличие {model} не обеспечивает явный выбор модели. Серьёзность:
критическая, блокер MVP. Достоверность: подтверждено. Потомок находки 1.
Валидация ищет маркер в любой части argv (machine_profile.py), а
подстановка лишь заменяет текст (critic.py). Валидна, например, команда с
единственным промптом «Прочти {launch_note}; заявленная модель {model}»,
но без -m/--model. Codex использует модель из пользовательской
конфигурации, тогда как каталог продолжает утверждать, что проход сделан
явно выбранной моделью.

3. Строка "false" открывает break-glass read-only. Серьёзность:
критическая, блокер модели угроз. Достоверность: подтверждено. Потомок
класса read-only и типизированной валидации. Аннотация bool в dataclass не
проверяется во время исполнения (machine_profile.py). После ручной записи
JSON "allow_unsafe_critic_sandbox": "false" значение оказывается истинным
в условии, и страж возвращает управление без проверки (readonly_guard.py).
Оператор, записавший обычное текстовое «false», получает запуск пишущего
критика вместо запрета. Другие неверные типы профиля дают сырой TypeError,
а не отказ с причиной и действием.

4. Реальная шапка Codex по-прежнему маскирует пустой ответ. Серьёзность:
высокая, блокер MVP. Достоверность: подтверждено. Потомок находки 4.
content_after_header пропускает только строки вида key: value
(readonly_guard.py), но настоящий вывод начинается с OpenAI Codex v…,
затем содержит разделители, user и исходный промпт — это видно, например,
в probe.log. Функция останавливается на первой строке и возвращает весь
вывод как содержательный. Codex без единой строки ответа всё равно даёт
непустой «проход» за счёт шапки и пользовательского промпта.

5. Проход и данные о судившейся версии записываются не как одно
восстановимое состояние. Серьёзность: высокая, блокер восстановления.
Достоверность: подтверждено. Потомок находок 7–8. Сначала write_pass
создаёт проход и метаданные только с received_at, а снимок артефакта и
версия профиля добавляются отдельной записью позже (cycle.py). При падении
между этими операциями восстановление видит проход, не переигрывает
критика, но _read_round_meta молча превращает отсутствующие или
повреждённые данные в {} (cycle.py). Новая сессия продолжает разбор, не
зная ни версии профиля, ни версии артефакта, которую видел критик.

6. Защита приватного каталога от Git действует только при создании.
Серьёзность: критическая для модели угроз публикации. Достоверность:
подтверждено. Потомок класса находок 9 и 11. Проверка вызывается только в
RunCatalog.create (runcat.py); восстановление и последующие записи её не
повторяют. Если правило .gitignore удалено или каталог принудительно
добавлен между кругами, следующий дословный проход записывается уже в
публикуемое место без отказа. Это именно предусмотренная оператором угроза
утечки через артефакты.

7. Дочерний процесс переживает успешное завершение непосредственного
родителя. Серьёзность: высокая, блокер живучести. Достоверность:
подтверждено. Потомок находки 6. Наблюдение заканчивается, как только
proc.poll() сообщает о выходе родителя; потоки чтения ждутся лишь десять
секунд, после чего результат принимается (subproc.py). Роль может породить
помощника, передать ему работу и завершиться с кодом 0: помощник продолжит
писать после того, как обвязка объявила роль законченной. Даже в ветке
тайм-аута код возврата Windows taskkill игнорируется (subproc.py), поэтому
сообщение об убитом дереве не подтверждено фактом.

8. Однословное русское отрицание исполняется как согласие. Серьёзность:
критическая для безусловного слова оператора. Достоверность: подтверждено.
Потомок находки 10. Проверка отрицаний знает только отдельные токены,
после чего ищет утвердительные основы как подстроки (gates.py). Ответы
«несогласен», «неподтверждаю» и «непринимаю» содержат основы соглас,
подтвержда или принима, поэтому возвращают True. В сценарии финализации
явный отказ оператора превращается в исполнение действия.

9. Ответы на пачку развилок долговечны для человека, но не для
восстановления цикла. Серьёзность: высокая. Достоверность: подтверждено.
Потомок находки 3. Каждый ответ сразу попадает в gates.md, но машинный
файл ответов создаётся только после завершения всего цикла вопросов
(cycle.py). Если в пачке два вопроса и процесс падает во время второго,
при восстановлении файл ответов отсутствует и первый вопрос задаётся
повторно. Два разных ответа одного оператора остаются в журнале без
однозначного состояния, возвращаемого разработке.

10. Восстановленный буфер может дослать в граф пару, которую API записи
отвергает. Серьёзность: высокая для целостности профиля. Достоверность:
подтверждено. Потомок исправления целостности пар. append вызывает
pair.validate, но pending только конструирует dataclass из JSON
(profile_sync.py). Строка с пустым сигналом либо реакцией без развёртки
принимается после перезапуска и отправляется через flush. В результате
повреждённое сырьё попадает в канон графа и способно молча исказить
производный профиль оператора.

11. Реализован один круг, но не автоматическое ведение цикла. Серьёзность:
критическая относительно финализированной спеки. Достоверность:
подтверждено. Новая территория. one_round запускает критика и разработку,
проверяет наличие исходов и возвращает номер (cycle.py); следующего
прохода после изменения артефакта не инициирует. CLI предоставляет только
ручную команду round (cli.py). Поэтому после каждой правки требуется новый
внешний запуск человеком или незаявленной машинерией, хотя спека разрешает
участие оператора только на воротах и требует инициировать следующий шаг
без него.

12. Пустой файл исходов считается состоявшимся разбором. Серьёзность:
высокая. Достоверность: подтверждено. Новая территория. write_outcomes
допускает пустой текст (runcat.py), а цикл проверяет только существование
файла (cycle.py). Разработка может завершиться с кодом 0, оставив пустой
или заранее существовавший файл; круг считается завершённым и состояние
переходит к следующему проходу, хотя ни одна находка не получила исхода.

13. Зелёная аттестация остаётся уже контракта. Серьёзность: высокая,
блокер приёмки. Достоверность: подтверждено. Потомок находки 13. Штатный
запуск дал 70 passed за 39,63 с, код возврата 0. Однако безопасная ветка
цикла не гоняется настоящим Codex: тест пустого прохода использует Python
с включённым break-glass, а тест шапки — сокращённую синтетическую шапку
без строки версии, разделителей и промпта (test_readonly_guard.py). Нет
сценариев для -o, текстового "false", модели без -m, аварии между проходом
и метаданными, смены Git-видимости каталога, морфологического отрицания,
падения внутри пачки вопросов, восстановленной невалидной пары, дочернего
процесса после выхода родителя, автоматического следующего круга и пустых
исходов.
