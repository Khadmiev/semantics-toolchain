# Круг 7 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после правок круга 6 (93 теста).
Тренд: 2 находки новой территории / 5 потомков прежних правок.
Вердикт критика: не готова — privacy на штатном пути разработки,
POSIX-дерево и сток стрима способны на ложный успех; решает оператор.

## Исходы (разработка; все — рабочий слой; 94 теста, pytest exit 0)

1. Privacy-класс не закрыт для стримов — **согласен**: стримы ролей идут
   под ежесекундным тиком надзора приватности (privacy_check в мониторе
   run_watched): каталог, ставший отслеживаемым посреди роли, останавливает
   роль в пределах тика с убийством дерева. Живой тест: критик сам удаляет
   .gitignore и продолжает печатать — роль убита тиком, не дожита.
   Формулировка тезиса исправлена: предотвращение в пределах тика, не
   «невозможность записи» (стримы пишет подпроцесс — абсолют недостижим,
   и описание больше этого не обещает).
2. POSIX-окно быстрого выхода родителя — **согласен**: pgid известен по
   построению (start_new_session ⇒ pgid = pid роли) и не спрашивается у ОС;
   ошибка killpg больше не выдаётся за подтверждение ни на timeout-, ни на
   reap-пути.
3. Ошибка/зависание записи стока невидимы — **согласен**: запись стока
   вынесена из-под замка монитора (зависший диск не ослепляет надзор за
   молчанием); ошибка записи фиксируется держателем и превращается в отказ
   роли с убийством дерева; отставший чанк в закрытый сток различается и
   отказом не является (текст цел в памяти и возвращается).
4. Невозможный порядок завершения кругов — **согласен**: исходы обязаны
   образовывать префикс истории 1..K; «исходы у круга 2 без круга 1» —
   отказ восстановления.
5. Контракт отказов не покрывает чтение — **согласен**: читатель каталога
   с контрактом (_read_text), чтение меты/проходов/исходов, чтение исходов
   в цикле, чтение и запись профиля машины — всё через HarnessError.
6. assert исчезает под python -O — **согласен**: структурные проверки
   переписаны явными ветками if/raise во всех местах разбора JSON.
7. Противоречие launch-note — **согласен**: тезис 7 переписан (штатно —
   stdin «-»; {launch_note} только под break-glass), заготовка profile-init
   рождается сразу в безопасной форме белого списка.

## Проход критика дословно

Тесты проходят: 93 passed. Исправлены metadata, пустые pass, git-head,
отрицательные окна, единый разбор ответов и обычный путь стриминга обоих
потоков. Семь существенных расхождений остаются.

1. [CRITICAL, подтверждено] Privacy-класс по-прежнему не закрыт. Описание
утверждает, что никакая ветка не пишет долговечный файл мимо проверки.
Однако run_watched() напрямую открывает stream-файл, а оба pump-потока
пишут в него без git-проверки; послепроверка выполняется только после
завершения разработки. Сценарий: разработка удаляет правило .gitignore,
затем продолжает выводить приватные данные в dev.log и записывает outcomes.
Harness обнаруживает проблему после завершения роли, но файлы уже находятся
в публикуемом дереве. Это обнаружение состоявшейся утечки, а не обещанная
невозможность записи. Тест проверяет только смену игнора между вызовами
write_pass(); штатную смену .gitignore внутри роли разработки он не
моделирует. Класс: MVP-блокер; потомок privacy-находки.

2. [HIGH, подтверждено] POSIX-гарантия дерева всё ещё имеет окно быстрого
выхода родителя. После Popen(start_new_session=True) код пытается получить
PGID через os.getpgid(proc.pid); если быстрый родитель уже завершился,
ошибка превращает _pgid в None, затем reap_survivors() считает такой путь
подтверждённым успехом. Дополнительно timeout-путь поглощает любой OSError
от killpg, не меняя confirmed=True. Класс: MVP для структурной изоляции.

3. [HIGH, подтверждено] Ошибка или зависание записи stream-файла невидимы
надзирателю. Pump пишет и flush-ит файл внутри фонового потока и внутри
общего lock. Два сценария: sink.write()/flush() бросает OSError — поток
молча умирает, роль может быть принята успешно; файловая операция
зависает — pump держит lock, и монитор не может вычислить молчание,
зависая сам. Тест покрывает только отказ первоначального open(). Класс:
MVP для долговечности и живучести.

4. [HIGH, подтверждено] Каталог принимает невозможный порядок завершения
кругов: pass 1 и pass 2 при outcomes только у круга 2 — restore()
принимает, resume_round возвращает круг 1, и разработка разбирает первый
круг после завершённого второго. Класс: MVP, порча собственных данных.

5. [HIGH, подтверждено] Общий контракт отказов не охватывает чтение и часть
записей: _load_meta() не ловит OSError чтения; чтение pass/outcomes при
восстановлении и в цикле необёрнуто; machine profile сохраняется обычным
write_text(). Диск с ошибкой чтения — сырой traceback. Класс: MVP.

6. [MEDIUM, подтверждено] Структурная валидация исчезает под python -O:
проверки JSON-структуры реализованы через assert в gate requests/answers и
metadata. Класс: приемлемый риск окружения; новая территория.

7. [MEDIUM, подтверждено] Контракт launch-note противоречит сам себе и
штатному scaffold: тезис 7 требует {launch_note} в команде критика, safe
guard разрешает только «-», validate() требует лишь {model}; profile-init
создаёт старую форму с {launch_note} и без «-» — scaffold не проходит
собственную валидацию. Класс: MVP-настройка; новая территория.

Тренд: 2 находки на новой территории / 5 потомков прежних правок.
Вердикт: не готова; финализацию решает оператор.
