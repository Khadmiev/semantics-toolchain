## Исходы (разработка; рабочий слой; 119 тестов, pytest exit 0)

1. Снимок без структурных границ — **согласен**: имя и содержимое
   кодируются 8-байтовыми префиксами длин перед склейкой; разные
   состояния каталога больше не сливаются в один хеш. Тест: файл «a» с
   «bc» против файла «ab» с «c» — снимки различаются.
2. Разрезанный многобайтовый символ — **согласен**: признак повреждения
   считается инкрементальным строгим декодером (буферизует разрез),
   а не разовым chunk.decode(); оборванный хвост на конце потока —
   по-прежнему повреждение. Тест: кириллическая «я», отданная двумя
   байтами с паузой 1,5 с, собирается без ложного raw-свидетельства.

## Проход критика дословно

Полный проход круга 18 выполнен. Исправление круга 17 работает: флаг
входных ворот без доказательства не записывается и не восстанавливается.
Тесты: 117 passed, код выхода 0.

1. [ВЫСОКАЯ] Снимок каталога допускает разные состояния с одинаковым
хешем: пути и содержимое файлов склеиваются без сохранения структурных
границ. Сценарий: файл `a` с содержимым `bc` и файл `ab` с содержимым
`c` оба дают хеш от байтов `abc` — переименование файла с
одновременной правкой начала содержимого выглядит для авто-цикла
неизменностью, и обязательный новый проход критика пропускается.
Класс: корректность снимка; новая территория.

2. [СРЕДНЯЯ] Валидный UTF-8 ошибочно признаётся повреждённым, если
многобайтовый символ разделён границей чтения: признак повреждения
считается разовым `chunk.decode("utf-8")` по каждому куску, тогда как
сам вывод собирается инкрементальным декодером. Сценарий: кириллица на
границе 64-КиБ чтения → ложное raw-свидетельство и пометка повреждения
на полностью валидном выводе. Класс: ложная тревога свидетельства;
новая территория.
