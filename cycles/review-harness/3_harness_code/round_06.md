# Круг 6 (третий прогон: код обвязки) — проход критика (sol) и исходы

Дата: 2026-09-01. Версия артефакта: после правок круга 5 (87 тестов).
Тренд: 4 находки новой территории / 6 потомков прежних правок.
Вердикт критика: не готова — публикация приватного после смены .gitignore,
неподтверждённая очистка дерева, восстановление битого прохода; решает
оператор.

## Исходы (разработка; все — рабочий слой; 93 теста, pytest exit 0)

1. Приватность не на каждой записи — **согласен, класс зашит в точку
   записи**: assert_outside_git выполняется внутри самой долговечной записи
   (мимо неё не пишет ни одна ветка), плюс перепроверка после разработки —
   исходы, записанные в ставший публикуемым каталог, не принимаются молча.
   Остаточная граница честна: файлы, которые пишет сам подпроцесс
   разработки в ходе работы, обвязка перехватить не может — она ловит это
   на приёмке исходов.
2. Смерть дерева не подтверждается на успехе; окно до Assign — **согласен**:
   reap_survivors возвращает подтверждение, неподтверждённое добитие —
   отказ и на успешном пути; на Windows роль рождается CREATE_SUSPENDED и
   оживает только после присоединения к джобу (гонка раннего потомка
   закрыта; ResumeThread через Toolhelp-снимок потоков).
3. stderr теряется из partial — **согласен**: оба потока стримятся в
   partial (порядок прихода), финальный транскрипт по-прежнему
   stderr-первым; тест: шапка из stderr цела на диске после таймаута.
4. Пустой/обрезанный pass — **согласен**: пустой текст не записывается;
   восстановление читает тело каждого прохода, пустое — громкое
   повреждение.
5. Дыра в последовательности кругов — **согласен**: история обязана быть
   непрерывной 1..N; пропавший круг — отказ восстановления.
6. Заглушка вместо git-головы — **согласен с различением**: ошибка git при
   существующей репе — громкий отказ; прогон вне рабочей копии — явное
   «вне-git» (законное отсутствие, не ошибка); заглушки ошибок полноту
   не проходят.
7. Дисковые отказы мимо HarnessError — **согласен**: долговечная запись
   оборачивает открытие/fsync/replace в отказ с причиной и действием.
8. Отрицательные окна — **согласен**: окно строго положительно,
   наблюдённый обрыв неотрицателен.
9. Каталог как исполняемый — **согласен**: исполнимость = файл с правом
   исполнения (is_file + X_OK).
10. Входные ворота со своим словарём — **согласен**: единый разборщик
    слова оператора (ask_yes_no) для входных ворот и подтверждений;
    «Да, подтверждаю описание» — согласие.

## Проход критика дословно

Тесты проходят: 87 passed. Исправления объединения потоков, stdin-доставки
launch note, метаданных и идиом согласия работают на покрытых путях. Однако
остаются нарушения несущих гарантий.

1. [CRITICAL, подтверждено] Приватность не проверяется на каждой
долговечной записи. Единственная общая проверка выполняется перед началом
круга (cycle.py). После этого разработка напрямую пишет dev.log через поток
подпроцесса; outcomes и gate requests из headless-роли; gate answers через
_write_durably() без _ensure_private(). Сценарий: разработка в ходе
нормальной правки удаляет или сужает правило .gitignore, а затем записывает
outcomes либо продолжает печатать dev.log. Приватный материал оказывается в
публикуемом дереве без отказа. Класс: MVP-блокер; потомок privacy-находки.

2. [HIGH, подтверждено] Успешное завершение родителя не гарантирует
подтверждённую смерть дерева. На штатном успешном пути reap_survivors()
игнорирует результат _terminate_job(); POSIX-ошибка killpg молча
поглощается. Требование «неподтверждённая смерть называется в отказе»
действует только на timeout-пути. Дополнительно на Windows процесс
запускается до создания и присоединения Job Object: быстро породившийся до
AssignProcessToJobObject потомок может не попасть в Job вообще. Класс: MVP
для изоляции ролей; потомок находки о process tree.

3. [HIGH, подтверждено] Частичный файл по-прежнему теряет весь stderr.
stdout передаётся в stream-файл, stderr собирается только в памяти. При
timeout или ненулевом коде полноценный pass не записывается, хотя сообщения
отказа утверждают, что полученный вывод цел в partial-файле. Сценарий:
Codex пишет шапку и причину отказа в stderr, после чего зависает — сведения
о песочнице и диагностике утрачиваются, хотя оператору сообщено обратное.
Класс: MVP для восстановления и диагностики; потомок stderr+stdout.

4. [HIGH, подтверждено] Пустой или обрезанный pass считается существующим
проходом. write_pass() не отвергает пустой pass_text; при восстановлении
содержимое файлов pass не читается. Сценарий: файл prohода обрезан до нуля;
каталог восстанавливает круг как имеющий проход и запускает разработку с
пустым ревью. Класс: MVP, порча собственных данных.

5. [HIGH, подтверждено] Потеря промежуточного круга не распознаётся:
восстановление не проверяет непрерывность последовательности; каталог с
кругами 1 и 3 молча продолжает с круга 4, скрывая потерю истории решений.
Класс: MVP для восстановимости; новая территория.

6. [HIGH, подтверждено] Заглушка считается настоящей git-головой: при любом
отказе rev-parse возвращается строка-заглушка, и проверка полноты принимает
её как корректный git_head. Происхождение по коммиту невосстановимо, мета
«полная». Класс: MVP для истинности метаданных.

7. [HIGH, подтверждено] Значительная часть дисковых отказов обходит
контракт HarnessError: _write_durably() не преобразует ошибки открытия,
записи, fsync и replace; CLI ловит только HarnessError. Диск заполнен —
пользователь получает сырой traceback. Класс: MVP; новая территория.

8. [MEDIUM, подтверждено] Отрицательные окна живучести проходят валидацию:
профиль с -1/-1 валиден, а первая проверка молчания немедленно убивает
живую роль. Класс: MVP-конфигурационный отказ; новая территория.

9. [MEDIUM, подтверждено] Проверка исполнимости принимает неисполняемые
пути: Path(exe).exists() истинно для каталога и для файла без права
исполнения. profile-check сообщает «исполним», первый запуск падает.
Класс: MVP-настройка машины; новая территория.

10. [MEDIUM, подтверждено] Входные ворота не используют заявленную
семантику ответов: безусловные ворота распознают развёрнутые ответы через
_read_yes_no, входные — отдельным точным набором строк. «Да, подтверждаю
описание» записывается как неподтверждение. Класс: UX-сбой, противоречие
тезису ворот; потомок морфологической находки.

Тренд: 4 находки на новой территории / 6 потомков прежних правок.
Вердикт: не готова; финализацию решает оператор.
