# v0.1.0 — the first public release

The checkable half of the article *Semantics Is the New Source Code*: a store where meaning
carries status and provenance, a review loop that is two texts and a thin harness, a
decompiler that reads back what was built, and gates where a person still decides.

This note is descriptive. Nothing an install or an update *requires* is carried here: the
install state machine of this version asks for it directly, and refuses with the stage that
is still open. If a note ever carries a required action with no predicate behind it, that is
a defect of the note.

## What this release is

A snapshot, not a mirror. The working repository is private and stays private; this one is a
distribution assembled from it by a manifest at release time, and reseeded at the next
version bump. Its history begins here on purpose.

The number is 0.1.0 rather than 1.0, and the reason is stated rather than implied:

- the installation runbook has **not** been walked end to end from this snapshot — no
  container was built from this tree, no owner logged in, no finishing probe was performed;
- **no upgrade path between snapshots is promised** at 0.x. Between pre-releases, recreate
  the database rather than expect a migration path from one snapshot to the next;
- parts of the product are deliberately absent (below), so the shape of the thing is settled
  but its edges are not.

What *was* checked, and how, is in the repository rather than in this paragraph: the whole
test suite runs inside this tree, and the schema was built from these migrations against an
empty database and compared with the author's own installation, table for table.

## What is here

- The graph store with its identity and policy schema, the MCP surface, the web surface,
  the scheduler, the install state machine, the operator profile.
- The review pair — two role texts, a few pages each — and the harness that carries them
  (`docs/review/`, `src/review_harness/`). A reading translation travels beside the Russian
  originals; the Russian file is the one the harness hands to the role.
- The audience genre, in the form it has at this snapshot: on the service-side machinery it
  was built on, not on the harness. The port travels in a later release.
- One complete development cycle, verbatim: `cycles/review-harness/` — the pair reviewing
  its own text, then the harness specification, then the harness code. 28 critic passes with
  development's outcomes and the operator's gates, in reading order.
- Five evidence dossiers of the incidents the article narrates (`evidence/`).

## What is not here

- The Telegram bot and the hyperparameter-optimisation module. Neither is promised by the
  article. Their settings survive in `config.py` and their tables in the migration history —
  the repository does not pretend those layers never existed.
- The working repository's own documents: design specifications, intents, review journals.
  This copy is the product; those are the author's process. The one specification the
  article's cycle judged travels inside that cycle, as the artifact that run reviewed.
- The records of the audience pilot. Eight tests that read them skip themselves here and say
  why.

## Known at the moment of release

- **The install has not been proven from this tree.** See above. If yours fails, that is
  worth reporting.
- **The harness understands Russian better than English.** Its messages are English, but the
  parser that reads the operator's yes/no answers grew around Russian: `yes`, `y`, `no`, `n`
  and `stop` are recognised, while an expanded English affirmative ("I confirm") is not — it
  will be asked again rather than misread. Being asked again is the designed behaviour for an
  answer that was not recognised.
- **Machine-facing text is still Russian** where translating it would change what a model
  receives: the prompts of the audience roles and the operating texts of the review pair.
  That is a change to the product with a live run of its own, not a text pass.
- Comments in the code cite the working repository's decision log, its review records and its
  graph node ids. They are traces of the process this project is about; nothing here needs
  them.
